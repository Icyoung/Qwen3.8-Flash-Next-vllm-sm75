# 面板自带「模型测试」实测对照：FIREFLY_AR 基线 vs PCIe-IPC 生产档

机器：G292-Z20，8 × Tesla T10（sm_75，纯 PCIe、无 NVLink）。
软件：vLLM-SM75 0.1.7-beta，官方模板 `flash-next-tp8-256k-nomtp`（TP8＋EP、256K、MMBT 4096、FP8 KV、QSA 全开、无 MTP）。
工具：Ultra 控制台自带「模型测试」（llm_speedtest 扩展，commit `eb19940`、sha `18b7b1d3`），并发数 1、超时 30 s，OpenAI 兼容接口。
**两批数据用的是同一把尺、同一台机、同一个 profile**，差别只有镜像层与那一个环境变量。

## 一、基线：`vllm-sm75:v0.1.7-ultra-beta-to20s`（后端 FIREFLY_AR）

ITL 带宽 22.89–23.25 ms，输出带宽 43.15–43.95 tok/s。
22.9 ms 正是这台机"关 MTP"的步时签名（另一档 MTP5 约 67 ms），可用来判断档位有没有跑错。

## 三、差值与判读

可比长度只有 512–8192 这五档：**基线那批只跑了 5 个长度**，16384 以上是生产档那轮才加上去的，不参与配对差。

| 指标 | 基线（5 档） | 生产档（9 档） | 变化（逐档配对） |
|---|---|---|---|
| ITL | 22.89–23.25 ms | **17.22–17.61 ms** | 每步省 **≈5.5 ms** |
| 输出 tok/s | 43.15–43.95 | **57.03–58.36** | **＋30.5%～＋33.1%** |
| 预填充 tok/s（512–8192 五档可比） | 2518.29–3105.99 | 2531.33–3117.93 | ＋0.4%～＋1.0%，**在噪声内** |
| TTFT（512–8192 五档可比） | 196.26 / 408.42 / 703.11 / 1334.89 / 2639.60 | 195.08 / 406.79 / 696.85 / 1328.91 / 2629.77 | −0.4% 左右 |

逐档配对（同一长度前后相除）：512 → ＋32.1%、1024 → ＋33.1%、2048 → ＋31.6%、4096 → ＋32.8%、8192 → ＋30.5%。
预填充逐档：＋0.99% / ＋0.52% / ＋0.96% / ＋0.47% / ＋0.38%。

三条判读：

1. **省的是每步固定开销，不是算力**。ITL 在 512 到 131072 九个长度上都稳定在 17.2–17.6 ms，与上下文长度无关；
   而 TTFT 与预填充吞吐几乎不动。这正是"每步一次 allreduce"的形状，与"某个内核变快"的形状不同。
2. **归因成立**。同一把尺、同一台机、同一个 profile，唯一改动是"镜像多一层回填 ＋ 环境变量置 1"。
   两者缺一不可：只有变量没有那层时，vLLM 会打印 `this FlashInfer build does not provide PcieIpcAllReduceWorkspace`
   并退回原后端（本机实测 decode 42.87，在基线噪声带内）；只有那层而不置变量时，vLLM 默认不启用该后端。
3. **不是提频、也不是解锁功率墙**。两次实测 SM 时钟都是 1590 MHz（T10 的跑满档），基线单卡约 90 W、生产档约 118 W，
   而每 token 能量几乎不变（2.06 → 2.03 J）。**这两个焦耳数是"功耗 ÷ 吞吐"算出来的计算值，不是仪器直接实测的量**，
   它的用途是做能量反算术、否掉"提频/解锁功率墙"这类机制假设。功耗上涨完全由"每秒多做 31% 的步"解释，别把功耗当机制。
   基线那侧的单卡功耗取自 2026-10-07 面板性能监控页的逐卡读数 **87.8–92.5 W**。

## 四、还没做的两件事（照抄前请知悉）

- 严格意义的"同容器只把变量设回 0"的 CLI 反向格未跑（物料在 `docker/pcieipc/`，一条 `SKIP_PCIEIPC=1` 即可产出对照镜像）。
  上面第 2 条的归因依赖的是"env 有、层没有"那一格与代码默认值判断，不是同容器单变量翻转。
- 跨会话/跨重启复现未做；本表是同一台机、相隔约 25 分钟的两批数据。

## 五、与官方文档数字的关系（重要）

官方文档写无 MTP 的 8K decode 是 49.93。作者镜像同样钉 FlashInfer 0.6.18，
其日志里 `FLASHINFER_PCIE_IPC` 只出现在候选后端、从未进实际选用 ⇒ **49.93 不是在 PCIe-IPC 生效下测出来的**。
所以这层回填不是"补齐我们和官方的差距"，而是官方产物当前拿不到的一条额外增益：
本机 8K 从 44.55 到 58.01（CLI 官方尺子口径），已高于 49.93 约 16%。
若要把它当生产长期配置，需接受"本机带一层自维护补丁"，并在上游 FlashInfer 带上该 workspace 后撤除。
